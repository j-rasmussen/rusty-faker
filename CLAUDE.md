# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Guidelines for maintaining production-grade Rust systems with extreme compile-time safety and optimal performance.

## What this is

`rusty-faker` is a drop-in replacement for Python's [Faker](https://github.com/joke2k/faker), with a Rust core exposed to Python through PyO3. Users write `from rusty_faker import Faker` and get Faker's API. v1 covers the `base`, `person`, `address`, `company`, `internet`, `lorem`, `phone_number` and `date_time` providers for `en_US`. Seeded output is repeatable within rusty-faker but is **not** byte-identical to Faker's.

## 🛠️ Build & Test Commands

Always use these exact commands for validation:
* **Build Project:** `cargo build`
* **Run Tests:** `cargo test`
* **Format Check:** `cargo fmt --check`
* **Strict Lints:** `cargo clippy --all-targets --all-features -- -D warnings`
* **Security Audit:** `cargo audit`

Python side (dev venv in `.venv`, created with `uv venv .venv && uv pip install --python .venv/bin/python "Faker==40.39.0" "maturin>=1.9.4,<2" pytest`):
* **Build + install the extension (editable):** `VIRTUAL_ENV=$PWD/.venv .venv/bin/maturin develop --uv` (add `--release` for benchmarking; re-run after any Rust change)
* **Compatibility tests:** `.venv/bin/python -m pytest -p no:faker tests` (`-p no:faker` disables the real Faker's pytest plugin, whose `faker` fixture clashes with ours)
* **Single Rust test:** `cargo test -p rusty-faker-core <name>`; **single Python test:** `.venv/bin/python -m pytest -p no:faker tests/compat/test_behavior.py::test_unique_and_optional`
* **Regenerate data:** `.venv/bin/python tools/extract_faker_data.py [--locale xx_XX]` (requires the pinned Faker 40.39.0)
* **Benchmark vs Faker:** `.venv/bin/python tools/bench.py --calls 20000`
* `cargo clippy` on `rusty-faker-py` needs a Python interpreter; set `PYO3_PYTHON=$PWD/.venv/bin/python` if it picks the wrong one.
* If linking fails with `exit status: 69` and "You have not agreed to the Xcode license agreements", either run `sudo xcodebuild -license` once, or build against the Command Line Tools instead: `export DEVELOPER_DIR=/Library/Developer/CommandLineTools`.

## Architecture

Three layers; a formatter call flows Python proxy → Rust method → static tables.

1. **Data ("the database")**: `crates/rusty-faker-core/data/<locale>/<provider>.json`, generated by `tools/extract_faker_data.py` from a pinned Faker. Never hand-edit it; re-extract. `crates/rusty-faker-core/build.rs` holds the `SCHEMA` (JSON attribute → Rust field, kind, required/optional). From it, the build script generates both the per-provider data structs and one `static` per locale, with precomputed cumulative weights and pre-tokenized `{{token}}` templates, into `OUT_DIR/data.rs` (included by `src/data.rs`). Nothing is parsed at runtime.
2. **Core crate** (`crates/rusty-faker-core`): `Generator` = seeded `Pcg64Mcg` + `&'static Locale` + `use_weighting`. Each provider is an `impl Generator` block in `src/providers/<provider>.rs`. Hot paths append to a `&mut String` (`write_*` methods) instead of allocating. Template tokens dispatch through the `Formatter` enum in `src/template.rs`; a data template using a token with no `Formatter` variant is a compile error in the generated code. Locale-specific behavior (e.g. the `en_US` postcode) branches on the generated `LocaleId`. Errors are `error::Error` variants, each mapped to the Python exception Faker raises.
3. **Bindings** (`crates/rusty-faker-py`, module `rusty_faker._core`): one `#[pyclass] Generator` whose method names and parameter names mirror Faker's (the compat tests enforce this). `FORMATTER_NAMES` must list every public formatter. Timezone-aware date/time calls are built here rather than in Python: Rust draws the timestamp and then makes one call into CPython's datetime — `attach_tz` (wall clock plus the zone, matching Faker's `datetime(1970,1,1,tzinfo=tz) + timedelta`) or `at_timestamp` (`fromtimestamp`, for the methods Faker converts with `astimezone`). Relative bounds such as `-30y` resolve against `Clock::Utc` when a zone is given and `Clock::NaiveLocal` otherwise, mirroring `datetime.now(tzinfo)` vs `datetime.now()`. The `*_this_*` methods still ask Python for the period boundaries, since those depend on the zone's offset at that wall-clock time. Only `time_series` and `pytimezone` remain in `python/rusty_faker/_tz.py`, which also keeps Faker's Python implementations as the reference the timezone tests compare against.
4. **Python package** (`python/rusty_faker`): `proxy.Faker` and `generator.Generator` are adapted from Faker's own classes. Key differences:
   - **Resolution order:** Python custom providers first, then the Rust core.
   - **Method cache:** resolved bound methods are cached in instance `__dict__`s. `Generator._invalidate()` clears them, and those of registered single-locale proxies, on `add_provider`/`seed_instance`. Anything that swaps `_core` must call it.
   - **RNG sharing:** unseeded generators share one Rust core per `(locale, use_weighting)` (`Generator._shared_cores`), mirroring Faker's module-level `random`. `seed_instance` swaps in a private core.
   - **Seeds:** `seed_to_u64` maps any seed type to u64.
   - **`fake.random`:** still a `random.Random`, used only by custom providers that call it directly.
   - **Unknown locales:** they fall back to `en_US` data.

Adding a formatter: implement it in the core provider file, add a `Formatter` variant only if data templates reference it, add the `#[pymethods]` wrapper plus a `FORMATTER_NAMES` entry, then rebuild with maturin. The compat tests check existence, signature and return type against Faker automatically for the v1 providers. Adding a locale: extract its data, make any attribute the locale lacks `opt(...)` in `SCHEMA`, and add `LocaleId` branches where Faker's locale subclass overrides methods.

## 🦀 Code Style & Architecture

* **Error Handling:** Never use `.unwrap()` or `.expect()` in production. Use `thiserror` for library crates and `anyhow` for binaries.
* **Memory Management:** Minimize resource clones. Pass references (`&str`, `&[T]`) instead of owned types (`String`, `Vec<T>`) where feasible.
* **Layout Standards:** Use early returns and guard clauses to minimize indentation depth. Keep modules focused and deeply encapsulated.
* **Safety First:** Mark unsafe code blocks explicitly with a detailed `// SAFETY:` comment justifying why the invariants hold true.

`unwrap_used`/`expect_used` are denied workspace-wide via `[workspace.lints.clippy]` (allowed in tests by `clippy.toml`). Code adapted from Faker keeps its MIT attribution; the license is in `LICENSE-faker`.
